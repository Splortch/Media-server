# Android phone: next implementation PR

Android is deliberately deferred until the API/Windows PR is reviewed. No empty application or unbuildable APK workflow is included. Continue issue #18 in this same monorepo, with dedicated `Android Client Alpha` milestone. Do not create another repository.

## Proposed modules

Create `clients/android` using Kotlin, Gradle Kotlin DSL, Jetpack Compose, Retrofit/OkHttp and Media3/ExoPlayer. Pin the Android Gradle Plugin, Gradle wrapper checksum, Kotlin/compiler and dependency versions after verifying their current compatibility. Put networking, security, models and playback in reusable Android library modules; the phone activity supplies Compose navigation and portrait/landscape UX. A future TV app reuses those libraries with its own interface.

## Reviewable PR sequence

1. **Network/security and real connection:** version check, URL validation, encrypted cookie storage, CSRF login/logout and revoked/expired-session tests. Generate Kotlin DTOs from `shared/api/openapi-v1.json`; do not copy EF entities. Use a bounded OkHttp client with TLS verification, explicit trusted redirects policy and no body/header credential logging.
2. **Phone library and Media3:** login → paginated search → details → authenticated Media3 Direct Play. Attach cookies on every video/range request. Fetch authoritative progress before playback, serialize expected-revision writes, stop on 409 and expose retry/reopen messages. Read track-selection capability flags; do not present unsupported choices as working.
3. **Phone release validation:** debug APK, unsigned release APK and unsigned AAB builds, JVM tests plus instrumentation against the actual backend using generated media. Debug APK must install and launch in an emulator. A release APK is not installable until signed; explain that explicitly. Produce artifacts with accurate names and independent `android-v...` versioning.

## Credential protection

Never store passwords. Generate a non-exportable AES-GCM key through Android Keystore; encrypt serialized session cookies in app-private storage with a unique random nonce per write. Prefer hardware-backed keys where available and report storage failures instead of falling back to plaintext. Exclude authentication blobs from backups because device-bound keys cannot be restored elsewhere. Clear blobs on logout even when remote revocation fails, and explain the unconfirmed server session. Do not use deprecated plaintext preferences as a shortcut.

Release builds require HTTPS for remote connections and must not globally permit cleartext or trust all certificates. Emulator development can use a tightly scoped, debug-only network-security configuration for its synthetic local server address, never packaged in release. Test actual backend authentication on the emulator, not just MockWebServer fixtures.

## Playback and platform behavior

Media3 selects device decoders; hardware support varies and needs device testing. Implement fullscreen/orientation restoration and local preferences first. Add Picture-in-Picture and Android media controls as focused follow-ups. Background audio needs an explicit user expectation, MediaSessionService and lifecycle/notification tests. Cast requires a separate authenticated receiver/token design; do not forward cookies or public media URLs to arbitrary receivers. Adaptive bitrate/network adaptation waits for authenticated server HLS (#4/#5). Offline downloads wait for a separately designed authorization and download lifecycle.

Signing keys and passwords belong outside source control, in protected CI secrets. Unsigned release outputs are acceptable while those secrets are unavailable; the debug keystore generated by Android tooling is test-only and must not be presented as release signing. Run lint, tests and clean Gradle assembly in an independent Android workflow once this real implementation exists.
